# Vanilla validation environment

M1 runtime qualification and live GTA validation require a **clean vanilla baseline**. Legacy DeFlux runtime artifacts in the game install or Documents config invalidate qualification results.

## Safe M1 build (default)

From the repository root:

```bat
build.cmd
build.cmd Debug
build.cmd Release
build.cmd Debug M1
```

These commands build **M1 targets only**:

- `DeFlux_Foundation`
- `DeFlux_GameAdapter_GtaSaDe`
- `DeFlux_Foundation_Tests`
- `DeFlux_Runtime`
- `DeFlux_Runtime_Harness`
- `DeFlux_TestClient`

They do **not** rebuild `DeFluxCore`, `version_proxy`, `DeFlux_Launcher`, or `DeFlux_Server`.

## M1 runtime directory safety (build output)

M1 executables live under `build\bin\<Config>\m1\`. Legacy outputs live under `build\bin\<Config>\legacy\`.

**Never place legacy `version.dll` beside M1 executables.** M1 tools import Windows `VERSION.dll` for PE file-version reads (`GetFileVersionInfoW`). When a legacy proxy shares the M1 output directory, Windows resolves that import to the proxy, which loads `DeFluxCore.asi` into the **M1 test process** — not necessarily GTA.

`DeFluxCore.log` sessions from the old shared `build\bin\<Config>\` layout are **not** reliable evidence that GTA ran.

The foundation provides `scan_m1_runtime_directory()` (filesystem-only) to reject M1 directories containing legacy loader artifacts. This is independent of GTA Win64 preflight.

## Explicit legacy / full build

Historical research only. Legacy outputs go to `build\bin\<Config>\legacy\`.

```bat
build.cmd Debug legacy
build.cmd Release full
```

Copying `build\bin\<Config>\legacy\version.dll` or `DeFluxCore.asi` into  
`Gameface\Binaries\Win64` **invalidates vanilla validation** until those files are removed and config is reset.

There is no automatic deploy command. Manual deployment is opt-in and must be treated as intentional environment contamination.

## Why legacy is excluded from the default build

Task #6 discovered that a normal `build.cmd Debug` rebuilt legacy artifacts, making accidental redeploy into the GTA install easy. The default M1 workflow must not produce `version.dll` or `DeFluxCore.asi` during everyday foundation/adapter/runtime development.

## Runtime qualification preflight

Before any live runtime qualification attempt (`GtaSaDeAdapter::qualify()` / `investigate()`), the adapter scans the **GTA executable directory** (parent of the verified `SanAndreas.exe` path from Task #4 observation).

If contamination is detected:

- status: `ENVIRONMENT_CONTAMINATED`
- no `OpenProcess`
- no GTA memory reads
- diagnostic lists detected artifacts

Run qualification only after the install directory is clean **and** Documents config has been regenerated by a normal GTA launch.

## Contamination artifacts

Detected in the executable directory (`Gameface\Binaries\Win64`):

| File | Reason |
| --- | --- |
| `version.dll` | Legacy DeFlux proxy loader |
| `DeFluxCore.asi` | Legacy injected runtime |
| `DeFluxCore.dll` | Legacy injected runtime |
| `DeFluxCore.log` | Legacy runtime session log |
| `deflux_entry_mode.txt` | Legacy launcher entry marker |
| `dinput8.dll` | Common ASI loader |
| `winmm.dll` | Common proxy/ASI loader |
| `dxgi.dll` | Common proxy/ASI loader |

Rockstar/Steam vanilla files beside `SanAndreas.exe` (for example `steam_api64.dll`, `MTLX.dll`) are **not** flagged.

## Config reset procedure

Legacy DeFlux modified user config under:

`Documents\Rockstar Games\GTA San Andreas Definitive Edition\Config\WindowsNoEditor\`

Affected files:

- `CustomSettings.ini` — zeroed ped/car density keys
- `GameUserSettings.ini` — `Traffic=0`

**Do not guess vanilla replacement values.**

Safe reset:

1. Back up the current files to a timestamped directory **outside** `WindowsNoEditor`.
2. Remove/rename the active `CustomSettings.ini` and `GameUserSettings.ini`.
3. Launch GTA normally once so Rockstar regenerates clean defaults.
4. Re-run M1 detection/qualification preflight.

Do **not** touch `Profiles\`, save files, or `GTASAsf8.sav` as part of config reset.
